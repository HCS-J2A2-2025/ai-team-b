# JobNavi Inteligens

就職活動データ分析・AI レポート生成システム

---

## 1. プロジェクト概要

JobNavi Inteligens は、本校における就職活動支援を目的として開発した
就職活動データ分析・AI レポート生成システムです。

学生が提出した就職活動レポート（説明会・面接記録など）を蓄積し、
そのデータを基にAIによる分析・要約を行うことで、

- 企業ごとの選考傾向の把握
- 学生個人の受験状況の整理
- 教員による就職指導の支援

を行うことを目的としています。

本プロジェクトでは、
機能の実装だけでなく、想定外の入力や操作をされた場合でも安全に動作するかを確認するため、
ペネトレーションテストを実施しました。

## 前提条件

本README内での使用するロール権限は、以下を指します。

- admin：管理者
- teacher：教員
- student：学生

## 2. 主な機能

### 2.1 企業別 AI レポート作成機能（JobNavi Inteligens）

過去に蓄積された就職活動レポート（CSV データ）を基に、
特定企業に関する選考の傾向を AI が分析。要約して表示する機能です。

表示される内容の例

- 面接の雰囲気
- よく聞かれる質問の傾向
- 服装
- 面接形式（オンライン／対面）
- 最新の面接記録（個人が特定できない形で表示）

#### 企業名入力の設計方針

企業名の検索は 完全一致のみ とし、
入力時には サジェスト（候補表示）機能 を用いて選択させています。

この設計には、以下の理由があります。

- 部分一致検索を許可すると、検索語を変えることで
  登録企業を推測できてしまう可能性があるため
- 表記揺れや入力ミスによって、
  実際に存在しない企業を対象に分析してしまうことを防ぐため

これにより、
必ずデータに存在する企業のみを対象に、正しい分析を行うことができます。

---

### 2.2 学生受験分析レポート機能

学生ごとの就職活動履歴を基に、
受験状況を整理。可視化する機能です。

確認できる内容の例

- 受験企業一覧
- 面接回数
- 合格率
- 面接形式・傾向
- 合否状況
- 活動期間の傾向

主に、教員・管理者が学生指導に活用することを想定しています。

---

### 2.3 CSV登録機能

就職活動データを常に最新の状態を保つため、CSVファイルを登録できる機能です。

- 登録可能なファイル形式はCSVファイルのみ
- 別形式のファイルをAIが学習することがありません
- 管理者のみが利用可能

とすることで、データの信頼性と安全性を確保しています。

### 2.4 他機能選択機能

他機能へ遷移するための選択機能です。

既存のJobNaviシステムでは複数機能を選択できる構成となっているため、
それに合わせて実装しています。

また、適切な権限を持たないユーザには一部の機能を表示しない仕様としています。

## 4. ログイン・権限管理について

本システムでは、認証（ログイン）機能そのものは
既存の仕組みを利用することを前提としているため、
本課題では新たに本格的なログイン機能は実装していません。

一方で、本システムには以下のような機能差があります。

- admin のみが利用できる機能
- admin・teacher のみが利用できる機能

そのため、ロールごとの画面遷移や機能制御を確認する目的で、
簡易的なログイン判定機能を実装しています。

---

## 5. フロントエンド側の安全対策

React Router を用いて画面遷移を管理し、
未ログイン状態で URL を直接入力した場合は、
ログイン画面（初期画面）へ戻る仕様としています。

これにより、

- ログインせずに画面を閲覧する
- 想定していない操作順で画面にアクセスする

といった使われ方を防いでいます。

---

## 6. API 設計における配慮

- `/api/company/report`
  - レポート内容は返さず、request_id のみを返却
- `/api/company/report/result`
  - 正しい request_id を指定した場合のみ結果を返却
- 存在しない、または改変された request_id は 404 エラー
- request_id は有効期限付きで管理
- 内部で使用している ID はそのまま返さず、公開用 ID を使用

これにより、
データの直接取得や推測を防いでいます。

## 7. ペネトレーションテスト

### 実施目的

作成したシステムが、
想定外の入力や操作をされた場合でも安全に動作するかを確認するため、
ペネトレーションテストを実施しました。

### 実施方法

- Burp Suite（Community Edition）を使用
- ブラウザを介さず、API に直接リクエストを送信
- 以下の点を確認

## 確認内容

- 不正なパラメータ送信
- 型の異なる値（数値・null など）の送信
- 必須項目が欠けたリクエスト
- request_id の一部改変、存在しない ID の指定

### 結果

- 不正な入力は 400 / 422 エラーとして処理される
- 無効な request_id は 404 エラーとなる
- サーバ内部エラー（500）は発生しなかった
- 学籍番号はサジェスト機能の仕様として、
  正常な入力時のみ候補が返ることを確認した

重大な脆弱性は確認されませんでした。
